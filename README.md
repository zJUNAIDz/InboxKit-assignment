# `Real-Time Grid` InboxKit Assignment(Cloudflare Workers + Durable Objects + React) 

A scalable, real-time collaborative grid application built on the Cloudflare Developer Platform and React. Users can connect concurrently, claim cells, and see updates instantly across all connected clients.

## Features
- **Real-Time Collaboration**: Multiple users can interact with the grid simultaneously.
- **Cell Claiming System**: Users can claim and unclaim individual cells on the grid.
- **Persistent State**: The grid's state is preserved continuously using Cloudflare Durable Objects storage.
- **Efficient Compute**: Utilizes Cloudflare's WebSocket Hibernation API, ensuring compute resources sleep while WebSocket connections are idle, keeping costs low.

## Architecture
The application leverages a highly scalable and edge-native architecture:

1. **Stateless Edge Routing (Cloudflare Workers)**: 
   The initial incoming requests from the client reach a stateless Cloudflare Worker acting as a lightweight API gateway (powered by Hono). The Worker authenticates (if needed) and forwards requests to the correct Durable Object instance.

2. **Stateful Coordination (Durable Objects)**:
   The core logic and state reside inside a Durable Object (`MyDurableObject`). Only one instance of this object coordinates the `global-grid`, preventing race conditions.
   - **Storage**: Grid state (cell ownership) is persisted asynchronously into the DO's built-in transaction-safe storage.
   - **Hibernating WebSockets**: The DO terminates WebSocket connections directly using the Hibernatable WebSockets API (`ctx.acceptWebSocket()`). This allows the Durable Object to "hibernate" (sleep) in the background while keeping thousands of WebSockets connected. Compute is only invoked—and billed—when a message is actively sent or received, enabling massive scale at a fraction of the cost.

3. **Client Sync**:
   Clients load the initial grid state via a standard HTTP REST call to the DO (`/grid`), then upgrade to a WebSocket connection (`/ws`). Through this connection, clients send `claim_cell` or `unclaim_cell` commands, and the DO broadcasts `update_cell` payloads to all active subscribers using `ctx.getWebSockets()`.

## How to Run Manually

The project is structured as a monorepo with `client` and `server` directories. [Bun](https://bun.sh/) is recommended as the package manager since it is used in the project configuration.

### 1. Start the Server (Cloudflare Worker)
Open a terminal and navigate to the `server` directory:

```bash
cd server
bun install
bun run dev
```
This launches Miniflare via Wrangler, emulating the Cloudflare Worker and Durable Objects locally. It typically runs on `http://localhost:8787`.

### 2. Start the Client (React App)
Open a new terminal and navigate to the `client` directory:

```bash
cd client
bun install
bun run dev
```
This starts the Vite development server. It typically runs on `http://localhost:5173`. 

Open the provided Vite local URL in your browser. You can open multiple browser windows side-by-side to test the real-time collaboration.

## Deployment
Both components are configured for deployment to Cloudflare using Wrangler.

- **Deploy Server**: `cd server && bun run deploy`
- **Deploy Client**: `cd client && bun run deploy` (Deploys to Cloudflare Pages/Assets via Wrangler)
